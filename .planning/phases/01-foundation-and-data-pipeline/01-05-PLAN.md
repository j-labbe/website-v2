    - Implement exactly as in research Pattern 4 (Atomic R2 Writes)

    Import everything: fetchContributionCalendar from github/graphql, createOctokit + fetchAllRepos + fetchRepoCommits + fetchRepoLanguages + fetchCommitDetail from github/rest, transformContributionCalendar from transform/graph, transformRepo + filterRepos from transform/projects, isBackfillNeeded from transform/backfill, readMeta + writePipelineResults + writeErrorMeta from r2.

    Define the structured log helper (same pattern as rest.ts).

    **Export `async function runPipeline(env: Env, forceBackfill?: boolean): Promise<void>`**

    Wrap the entire body in try/catch. On catch: call writeErrorMeta with the error message and re-throw (so ctx.waitUntil sees the rejection for logging).

    **Pipeline steps:**

    1. **Read existing meta** to determine backfill vs incremental:
       ```
       const meta = await readMeta(env.R2_BUCKET);
       const backfill = forceBackfill || isBackfillNeeded(meta);
       log("pipeline-start", { mode: backfill ? "backfill" : "incremental" });
       ```

    2. **Fetch contribution calendar** (always 12 months, regardless of mode):
       ```
       const calendar = await fetchContributionCalendar(env.GITHUB_TOKEN, "j-labbe");
       const graphData = transformContributionCalendar(calendar);
       ```

    3. **Fetch all repos:**
       ```
       const octokit = createOctokit(env.GITHUB_TOKEN);
       const allRepos = await fetchAllRepos(octokit);
       log("repos-fetched", { total: allRepos.length });
       ```

    4. **For each repo, fetch languages + commits + transform:**
       - Determine date range: backfill = 24 months ago to now; incremental = meta.lastUpdated to now
       - For each repo:
         a. Fetch languages via fetchRepoLanguages
         b. Fetch commits via fetchRepoCommits with author="j-labbe" and date range
         c. Aggregate commits into monthlyCommits: Record<string, number> (key = "YYYY-MM", value = count)
         d. For PUBLIC repos only: fetch up to 10 recent commit details via fetchCommitDetail (with rate limit checking). Map to CommitDetail[].
         e. Call transformRepo(raw, monthlyCommits, languages, recentCommits)
       - Collect all ProjectEntry results
       - Log progress every 10 repos: log("repos-processed", { current, total, rateLimitRemaining })

    5. **Filter repos:**
       ```
       const projects = filterRepos(allEntries);
       log("repos-filtered", { before: allEntries.length, after: projects.length });
       ```

    6. **Write to R2:**
       ```
       await writePipelineResults(env.R2_BUCKET, graphData, projects);
       log("pipeline-complete", { projectCount: projects.length });
       ```

    **Important implementation details:**
    - Per user decision: username is "j-labbe"
    - Per user decision: 24-month window for project timeline, 12-month for graph
    - Per user decision: filter repos with <3 commits
    - Per user decision: daily cron at 06:00 UTC (configured in wrangler.toml from Plan 02)
    - Per research: rich commit data (messages, diff stats) only for public repos, max 10 recent commits per repo to manage API budget
    - Per research: on rate limit approaching (<200 remaining), skip remaining commit detail fetches, log warning, continue with what we have
    - Per research discretion: auto-detect backfill when meta.json missing or >48h stale

    Update the Worker entry point from stub handlers to real handlers that call runPipeline. Create the R2 CORS policy file.

    **worker/src/index.ts:** Replace the stub from Plan 02 with real handlers.

    Keep the existing Env interface (R2_BUCKET, GITHUB_TOKEN, REFRESH_SECRET).

    ```typescript
    import { runPipeline } from './pipeline';

    export default {
      async scheduled(
        controller: ScheduledController,
        env: Env,
        ctx: ExecutionContext,
      ) {
        console.log(JSON.stringify({ stage: "cron-triggered", ts: Date.now() }));
        ctx.waitUntil(runPipeline(env));
      },

      async fetch(
        request: Request,
        env: Env,
        ctx: ExecutionContext,
      ): Promise<Response> {
        // Only POST triggers pipeline refresh
        if (request.method !== "POST") {
          return new Response("Method not allowed", { status: 405 });
        }

        // Bearer token auth
        const authHeader = request.headers.get("Authorization");
        if (authHeader !== `Bearer ${env.REFRESH_SECRET}`) {
          return new Response("Unauthorized", { status: 401 });
        }

        // Check for explicit backfill parameter
        const url = new URL(request.url);
        const forceBackfill = url.searchParams.get("backfill") === "true";

        // Trigger pipeline (non-blocking via waitUntil)
        ctx.waitUntil(runPipeline(env, forceBackfill));
        return new Response(
          JSON.stringify({ status: "triggered", backfill: forceBackfill }),
          { status: 202, headers: { "Content-Type": "application/json" } }
        );
      },
    };
    ```

    Note: This means runPipeline needs to accept an optional `forceBackfill?: boolean` parameter. Update pipeline.ts signature to: `runPipeline(env: Env, forceBackfill?: boolean)`. When forceBackfill is true, skip the meta check and go straight to backfill mode.

    **cors.json** (repo root): R2 CORS policy file for applying via `wrangler r2 bucket cors set`.

    Per research: this is applied via `wrangler r2 bucket cors set jacklabbe-data --file cors.json` after R2 bucket creation. The command is run during deployment, not during build.
